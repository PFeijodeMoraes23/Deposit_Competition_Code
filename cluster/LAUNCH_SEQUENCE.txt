5. LAUNCH
------------------------------------------------------------------------------
     bash pipeline_all.sh --blp-args "--draws --sysimage"

   *** --blp-args IS NOT OPTIONAL ON THIS CLUSTER. ***
   blp_run.sh defaults to DO_SYSIMAGE=0 and DO_DRAWS=0 -- it assumes both exist.
   Without the flags the BLP phase either refuses on missing draws or, worse,
   runs with no sysimage: CUDA.functional() fails, the CF stack catches it and
   silently falls back to CPU while holding an H200.

   --skip-preflight is NO LONGER NEEDED. G0 now passes on its own.

   EXPECT THE LIVE RUN TO STOP AFTER THE LOGIT PHASE. That is by design: a
   continuation job resumes at --from blp once G2 and G4 pass, because
   blp_run.sh/bbl_run.sh/cf_eq_run.sh preflight their inputs at SUBMIT time and
   those inputs do not exist at t=0. squeue will show far fewer jobs than the
   dry run printed. This is correct.

6. WATCH
------------------------------------------------------------------------------
     squeue -u $USER
     ls -la data/output/.gate_*.json

   FIRST REAL SIGNAL -- gate G1, after the estimators:
       cat data/output/.gate_G1.json
   It compares cluster phi-hat against the promoted local values
       E1 99.9945   E2 99.5400   E3 96.5627   E4 96.6814
   The multistart caps at 8 threads / 4 starts on ANY node size, so these SHOULD
   match. A match validates the whole port end to end. A move is a red flag worth
   stopping for -- the gate reports it and never fails the chain.

   Gate order: G1 estimators -> G2 demand parquets -> G3 AME / G7 upsilon,
   G4 after the logit. Each writes its json BEFORE exiting.

   IF A GATE FAILS its downstream cone is cancelled as DependencyNeverSatisfied
   and those jobs write NO log at all. Read the .gate_*.json first, then the .err
   of the job that actually failed -- not the silent ones.

   GPU capacity: gpu_h200 allows 6 concurrent jobs. The cf3 sweeps submit
   --array=0-39 GPU arrays, so they drain 6 at a time. Slow, not broken.
